# Add an LLM step to an integration

This sample is an HTTP service that triages customer support tickets. Each ticket is validated against constraints on the `Ticket` type, then classified by a direct LLM call (`model->generate(...)`) whose response is bound to a typed `Triage` record (category, priority, and a one-sentence summary). The result is validated against business rules, routed to a queue by deterministic Ballerina code (urgent tickets always go to the on-call queue), and, if the model call fails or returns an unusable response, the ticket falls back to a manual triage queue so it is never lost.

This sample accompanies the [Add an LLM step to an integration](https://ballerina.io/learn/add-an-llm-step-to-an-integration/) guide.

## Prerequisites

- Ballerina 2201.13.0 (Swan Lake Update 13) or later
- An OpenAI API key

## Configure

Copy `Config.toml.example` to `Config.toml` and set your OpenAI API key.

```toml
openAiApiKey = "<YOUR_OPENAI_API_KEY>"
```

## Run

```
$ bal run
```

## Try it

Submit a ticket. Because the classification is generated by an LLM, your results will differ.

```
$ curl -X POST http://localhost:8080/support/tickets \
    -H "Content-Type: application/json" \
    -d '{"subject": "Charged twice for my subscription", "body": "I was billed two times this month for the Pro plan. Please refund one of the charges."}'
{"queue":"billing", "triagedBy":"MODEL", "category":"BILLING", "priority":"HIGH", "summary":"The customer was charged twice this month for the Pro plan and requests a refund."}
```

With an invalid API key in `Config.toml`, the model call fails and the same request is routed to the manual triage queue.

```
{"queue":"manual-triage", "triagedBy":"FALLBACK", "category":"OTHER", "priority":"MEDIUM", "summary":"Charged twice for my subscription"}
```

A ticket with an empty subject is rejected with `400 Bad Request` without calling the model.

```
$ curl -i -X POST http://localhost:8080/support/tickets \
    -H "Content-Type: application/json" \
    -d '{"subject": "", "body": "The app crashes on startup."}'
HTTP/1.1 400 Bad Request
```

## Test

The tests cover the deterministic logic (validation, routing, and fallback) and do not call the model. `tests/Config.toml` provides a placeholder key.

```
$ bal test
```
