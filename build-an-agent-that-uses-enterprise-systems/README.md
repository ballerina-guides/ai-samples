# Build an agent that uses enterprise systems

An online store's support assistant that customers chat with about their orders. The agent uses typed function tools (`getOrder`, `cancelOrder`) and an `ai:HttpServiceToolKit` tool (`getShipment`) over existing order and shipment APIs, keeps per-session conversation memory, limits the number of iterations per request, validates input before it reaches a backend, returns business errors to the model, and fails the request with `503 Service Unavailable` when the order system is down. The order and shipment APIs are mocked by a service in the same package (`backend.bal`), so the sample runs end to end without external systems.

For a step-by-step walkthrough, see the guide: [Build an agent that uses enterprise systems](https://ballerina.io/learn/build-an-agent-that-uses-enterprise-systems/).

## Prerequisites

- Ballerina 2201.13.0 (Swan Lake Update 13) or later
- An OpenAI API key (any model provider that supports tool calling can be used; see the guide)

## Configure

Copy `Config.toml.example` to `Config.toml` and set your OpenAI API key.

```
$ cp Config.toml.example Config.toml
```

```toml
openAiApiKey = "<YOUR_OPENAI_API_KEY>"
```

The other configurable variables (`orderApiUrl`, `memorySize`, `maxIterations`, `servicePort`, `backendPort`) have defaults and can be overridden in the same file.

## Run

```
$ bal run
```

This starts the mock backend on port `9090` and the chat service on port `8080`.

## Try it

Replies are generated by an LLM, so your results will differ.

```
$ curl -X POST http://localhost:8080/support/chat \
    -H "Content-Type: application/json" \
    -d '{"sessionId": "customer-42", "message": "Where is my order ORD-1001?"}'
{"message":"Your order ORD-1001 (1 x Mechanical keyboard) has shipped with FastShip. It is in transit and is expected to arrive on 2026-10-15."}
```

A follow-up in the same session, resolved through conversation memory:

```
$ curl -X POST http://localhost:8080/support/chat \
    -H "Content-Type: application/json" \
    -d '{"sessionId": "customer-42", "message": "Can I still cancel it?"}'
{"message":"Order ORD-1001 has already shipped, so it can't be cancelled."}
```

Cancelling a pending order (the agent asks for confirmation first):

```
$ curl -X POST http://localhost:8080/support/chat \
    -H "Content-Type: application/json" \
    -d '{"sessionId": "customer-7", "message": "Please cancel ORD-1002, I ordered it by mistake."}'
{"message":"Order ORD-1002 contains 2 x Wireless mouse for a total of $49.98. Do you want me to cancel it?"}
```

An invalid request is rejected without calling the model:

```
$ curl -i -X POST http://localhost:8080/support/chat \
    -H "Content-Type: application/json" \
    -d '{"sessionId": "", "message": "Where is my order?"}'
HTTP/1.1 400 Bad Request
...
sessionId must not be empty
```

To see the outage handling (`503 Service Unavailable`), point the order API to a port where nothing is listening and ask about an order:

```
$ bal run -- -CorderApiUrl=http://localhost:9999/api
```

## Test

The tests cover the tools, input validation, and error mapping, and do not call the model. `tests/Config.toml` provides a placeholder API key.

```
$ bal test
```

The connection-failure test logs an `Order API call failed` error, which is expected.
