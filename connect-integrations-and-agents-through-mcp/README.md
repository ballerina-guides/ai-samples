# Connect integrations and agents through MCP

An online store publishes its catalog and order operations (product search, order status lookup, return requests, and refunds) once, as tools on a Model Context Protocol (MCP) server, so that any AI client can use them. A customer-facing Ballerina AI agent connects to that server with an `ai:McpToolKit` that loads only the tools it is permitted to use (it cannot issue refunds), keeps running when the MCP server or the model is unavailable, and maps each kind of failure to an HTTP status code. The sample has two packages: `customer_care_mcp_server` (the MCP server) and `customer_care_agent` (the agent service).

For the full walkthrough, see the guide [Connect integrations and agents through MCP](https://ballerina.io/learn/connect-integrations-and-agents-through-mcp/).

## Prerequisites

1. Ballerina 2201.13.0 (Swan Lake Update 13) or later.
2. An OpenAI API key (for the agent only; the MCP server does not need a model).
3. Optionally, Node.js, to inspect the MCP server with the MCP Inspector.

## Configure

The MCP server needs no configuration (it listens on port `9090` by default). To change the port, copy `customer_care_mcp_server/Config.toml.example` to `customer_care_mcp_server/Config.toml` and edit it.

For the agent, copy `customer_care_agent/Config.toml.example` to `customer_care_agent/Config.toml` and set your key.

```toml
openAiApiKey = "<YOUR_OPENAI_API_KEY>"
mcpServerUrl = "http://localhost:9090/mcp"
```

## Run

1. Start the MCP server first.

    ```
    $ cd customer_care_mcp_server
    $ bal run
    ```

2. In a second terminal, start the agent service.

    ```
    $ cd customer_care_agent
    $ bal run
    ```

## Try the MCP server

List the tools.

```
$ curl -X POST http://localhost:9090/mcp \
    -H "Content-Type: application/json" \
    -H "Accept: application/json, text/event-stream" \
    -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Call a tool.

```
$ curl -X POST http://localhost:9090/mcp \
    -H "Content-Type: application/json" \
    -H "Accept: application/json, text/event-stream" \
    -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"getOrderStatus","arguments":{"orderId":"ORD-1002"}}}'
{"jsonrpc":"2.0", "id":2, "result":{"content":[{"type":"text", "text":"{\"orderId\":\"ORD-1002\",\"state\":\"SHIPPED\",\"skus\":[\"SP-300\",\"CB-400\"],\"placedOn\":\"2026-10-05\",\"deliveredOn\":null}"}]}}
```

To browse and call the tools interactively, run the MCP Inspector.

```
$ npx @modelcontextprotocol/inspector
```

In the Inspector, select **Streamable HTTP** as the transport type, enter `http://localhost:9090/mcp` as the URL, and connect. Then list the tools and run them with test arguments.

## Try the agent

The replies are generated by an LLM, so your results will differ.

```
$ curl -X POST http://localhost:8080/support/chat \
    -H "Content-Type: application/json" \
    -d '{"sessionId": "cust-42", "message": "Do you have wireless headphones in stock?"}'
{"reply":"Yes. The Wireless headphones (HP-100) are in stock at $79.99. The Noise-cancelling wireless headphones (HP-200) are currently out of stock."}
```

Continue the conversation with the same session ID.

```
$ curl -X POST http://localhost:8080/support/chat \
    -H "Content-Type: application/json" \
    -d '{"sessionId": "cust-42", "message": "I want to return ORD-1001. It arrived damaged."}'
{"reply":"To confirm: you want to return order ORD-1001 because it arrived damaged. Shall I submit the return request?"}
```

The MCP server logs each tool call. If you ask the agent to issue a refund, it cannot, because `issueRefund` is not in its permitted tools.

An invalid session ID is rejected without calling the model.

```
$ curl -i -X POST http://localhost:8080/support/chat \
    -H "Content-Type: application/json" \
    -d '{"sessionId": "cust 42", "message": "Hi"}'
HTTP/1.1 400 Bad Request
...
sessionId must have 1 to 64 letters, digits, '-', or '_'
```

Stop both services, start only the agent service, and send a message. The agent cannot connect to the MCP server, so it responds with `503`. Start the MCP server and send the message again; the agent connects without a restart.

```
$ curl -i -X POST http://localhost:8080/support/chat \
    -H "Content-Type: application/json" \
    -d '{"sessionId": "cust-42", "message": "Where is my order ORD-1002?"}'
HTTP/1.1 503 Service Unavailable
...
Customer care is temporarily unavailable. Try again later.
```

## Test

Run the tests in each package. Neither test suite needs a real OpenAI key or a running MCP server: the server tests use port `9191`, and the agent tests start a mock MCP server on port `9292` and use the placeholder key in `tests/Config.toml`.

```
$ (cd customer_care_mcp_server && bal test)
$ (cd customer_care_agent && bal test)
```

The agent's `testChatReturns503WhenMcpServerIsDown` test logs a `Cannot connect to the MCP server` error. This is expected.
